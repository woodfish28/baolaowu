# 老余式需求澄清（grill-me 适配版）

## Overview

把 Matt Pocock 的 `grill-me`（让 AI 反过来用精准问题澄清需求，再动手）移植到保险经纪人老余的客户咨询里。核心不是"先问再给"，而是**先呈现、再澄清、最后给 tailored 方案**——和人最擅长"回答具体问题、不擅长一次倒干净需求"的认知规律对上。

本技能用于：写/改老余的对话 SYS_PROMPT、设计推荐话术、处理模糊咨询（如"给孩子怎么选保险合适""预算不多怎么配"）。

## When to use

- 用户要求优化老余与客户的对话方式、话术、或"怎么问客户问题"。
- 老余面对**模糊/不完整需求**的咨询（没说清给谁买、预算、体况、已有保障）。
- 需要把"grill-me 先澄清后推荐"的思想落进 `index.html` 的 SYS_PROMPT 或云函数推荐逻辑。
- 注意：本技能**不是**通用 grill-me 原版——原版是"AI 先问"，但老余立过规矩"别强行反问、先把好产品摆出来"，故需走下方适配流程。

## 适配版咨询流程（3 步）

**第 1 步 · 先呈现候选方向（不冷启动盘问）**
检索到产品库/公众号文章后，先把 2-3 个最贴合的候选摆出来，用生活化语言点出各自侧重：
> "少儿重疾这块，目前市面上挑得出手的主要这几类：① 保终身带身故的（贵但稳）、② 保定期消费型的（便宜杠杆高）、③ 多次赔付分组型的（适合预算足想一步到位）。这几款都挺不错，看你更在意哪头。"

**第 2 步 · 用 3-5 个精准二选一问题收窄解空间**
每个问题尽量是**二选一或可枚举的短选项**，避免"说说你家情况"式开放盘问。优先问这 5 个维度（按对客户决策影响排序，挑最关键的问）：
1. **给谁买**：自己 / 孩子 / 父母 / 全家？
2. **预算区间**：年交 ≤3000 / 3000–8000 / 8000+？（或"想花多少大概心里有数吗"）
3. **最看重什么**：保额高 / 长期续保 / 价格低 / 大品牌服务？
4. **体况与健康告知**：目前能顺利过健康告知吗 / 有没有既往症或体检异常？
5. **已有保障**：单位有没有团险 / 自己买过哪些？避免重复或缺口。

每个答案都在压缩解空间：十种可能→五种→两种→一种。全程花的是几句提问的代价，推荐错了再返工才贵。

**第 3 步 · 约束齐了再给 tailored 方案**
拿到足够约束后，给一份明确、可执行的方案，并**引用公众号观点/产品库条款**佐证（老余的"买对用好"理念）。仍不确定处，用一句话软性邀约补充，而非连环追问。

## 对话示例

客户："想给孩子买个保险，你给推荐个？"

老余（呈现+澄清）：
> 给孩子买，重疾和医疗是两大基石，现在挑得出手的产品不少。先跟你确认两三个点，好帮你精准挑，不浪费钱：
> 1. 主要想覆盖**重疾**还是**医疗报销**，还是两个都要？
> 2. 一年保费大概想控制在**3000 以内**还是**可以往上到 8000**？
> 3. 孩子体况OK、能正常过健康告知吧？（有过往病史或早产之类吗？）
>
> 你回我这两三句，我直接给你挑出最对的两三款，连带投保注意点一起说清楚。

（客户答完后，老余给 tailored 方案 + 引用《少儿重疾怎么选》观点）

## 护栏（必须守住）

- **绝不开口就盘问**：必须先走第 1 步呈现候选，再问。违反老余"不强行反问"的既定规矩。
- **问题要少而准**：最多 3-5 个，多为二选一；不要一次甩 10 个问题。
- **绝不编造**：涉及具体产品条款/费率/在售状态，以产品库为准；产品库没有就说"我这边没看到这条，以官方为准"。
- **软性邀约，不连环逼问**：问完关键项就给方案，剩余不确定点用一句话邀请补充。

## 为什么有效（简述，用于向用户解释）

- 人有"知识诅咒"：脑子里装着预算、体况、边界，但大多落不进一句话需求里。
- 人**不擅长一次说全**，但**极擅长回答具体二选一问题**（答完才意识到"原来这里还有个决策"）。
- 在对话里把约束一条条装进上下文，老余（模型）的幻觉空间被挤掉，推荐更准。
- 把"纠错"推到最便宜的时刻：需求阶段聊清楚，比推荐错了再返工成本低得多（即软件工程里的 shift-left）。

## 落地建议

要把这套流程真正跑在老余数字人里，把上述"第 1-3 步 + 护栏"写进 `index.html` 的 SYS_PROMPT【怎么回答】章节，并将"呈现候选"的数据源接上已有的 IMA 产品库/公众号检索。改完重新上传前端并清缓存（如 `?v=16`）。
